
## 현재 디자인 진단

전체 톤(네이비/골드/파치먼트, Noto Serif/Sans KR)과 레이아웃 골격은 이미 견고합니다. 다만 페이지를 하나씩 비교하면 다음과 같은 **일관성·완성도·UX 측면의 개선 여지**가 발견됩니다.

---

## 1. 글로벌 일관성 문제

### 1-1. CTA 버튼 스타일이 페이지마다 제각각
- 홈: `rounded-sm bg-gold px-7 py-4`
- 계약: `rounded-sm px-6 py-3`
- 문의: `rounded-sm bg-ink px-6 py-4`
- 헤더: `rounded-sm bg-ink px-5 py-2.5`
→ shadcn `Button` 컴포넌트는 있지만 거의 사용하지 않음. **`primary` / `gold` / `outline` 3가지 변형으로 통일**.

### 1-2. 헤더 로고와 푸터 로고가 색상이 반전됨에도 톤이 어긋남
- 헤더: `bg-ink text-gold` / 푸터: `bg-gold text-ink`
- 푸터의 골드 박스가 다크 배경에서 너무 튀어 위계를 흐림 → 푸터 로고도 헤더와 동일 톤(`bg-gold/10 text-gold border border-gold/30`)으로 차분하게.

### 1-3. "관리자" 링크가 푸터 맨 아래에 노출
- 일반 사용자에게 보일 필요 없음 → 작은 점/저작권 옆 거의 보이지 않게 처리하거나, 키보드 단축(`?` 또는 `/admin` 직접 접근)으로 숨김.

## 2. 홈페이지 (index.tsx)

### 2-1. Hero 영역
- 모바일에서 `text-5xl` + `py-32`가 스크롤 부담 → `py-24 md:py-48`로 단계화.
- 두 개의 CTA가 동일 weight여서 시선이 분산됨 → 골드(주)+텍스트 링크(보조) 또는 `Button` 컴포넌트로 위계 명확화.
- Hero 하단에 **"신뢰 지표(라이센스 번호, 한국공인회계사회 등록 등)"** 1줄 추가하여 즉시 신뢰감 확보.

### 2-2. 통계/사례 섹션 시각화 부족
- "62% / 3.4억 / 11년" 통계가 단순 텍스트만 → 얇은 진행 바·아이콘 1개씩 추가.
- "Real Evidence" 4 stat 박스는 이미 골드 숫자가 있어 좋음 — 호버 시 `bg-card → bg-parchment` 미세 트랜지션 추가.

### 2-3. 방송 카드의 고정 너비(`w-40`)
- 작은 모바일에서 이미지 비중이 과해 텍스트가 좁아짐 → `w-32 sm:w-40`로 반응형.

---

## 3. 시뮬레이터 (simulator.tsx)

### 3-1. SUMMARY BAR 가독성
- ink 배경 위 `bg-destructive/20` 박스가 빨간 톤으로 강조되지만, 옆 셀과의 시각적 위계가 약함 → 강조 셀에 좌측 골드 보더(`border-l-2 border-gold`) 추가.

### 3-2. 슬라이더 라벨이 작음
- `text-sm`+회색이라 입력 필드인지 인지가 늦음 → 라벨을 `text-base font-medium text-foreground`로 승격, 도움말 텍스트(`예: 강남권 1,000세대 평균 약 ~`) 1줄 추가.

### 3-3. Phase 탭 카드 활성화 표시
- 현재 `border-gold + bg-gold/5`만으로 활성. 모바일에서 골드가 약함 → 활성 시 카드 상단 2px 골드 인디케이터 추가.

### 3-4. 리스크 테이블
- 데스크톱에서 `grid-cols-[1fr_120px_120px_160px]` 4열이 스크롤 없이 잘 보이지만, **모바일(<640px)에서 너무 좁음**. 모바일 한정 카드형 리스트로 전환.

---

## 4. 계약 페이지 (contract.tsx)

### 4-1. Featured(Premium) 카드가 시각적 우위가 약함
- 단순 ink 배경 변경. 인기 표식(`MOST POPULAR` 배지)·상단 +6px 솟음 효과·골드 그림자를 더해 선택 유도.

### 4-2. 가격 카드가 데스크톱에서 너무 길쭉
- `flex flex-col p-10` → 내부 간격(`mt-10 mt-8 mt-6`)이 과도. `p-8 md:p-10`로 살짝 콤팩트하게.

### 4-3. Terms `<dl>` 영역
- `md:col-span-3 / 9` 비율이 좋으나 모바일에서는 키-값이 같은 줄로 보이지 않아 스캔 어려움 → `dt`를 `text-xs uppercase`로 승격하고 `dd`와의 여백 차별화.

## 5. 서비스 (services.tsx)

### 5-1. 섹션 간 `space-y-32`가 너무 큼
- 두 카드만 있을 때는 적당하나, CMS로 항목이 늘어나면 스크롤 피로 → `space-y-24`.

### 5-2. 큰 골드 숫자(`text-7xl`)와 `hairline` 사이가 어색
- `hairline w-24` 위치를 숫자 아래가 아니라 좌측 정렬 영역 전체 폭으로 → 시각적 구획.

### 5-3. 체크리스트 아이콘
- `CheckCircle2`가 다소 카지얼. 골드 색상 + 라인 아이콘이 사이트 톤과 맞지 않음 → 작은 정사각 골드 점(`■`) 또는 `Check`(가는 stroke 1.2) 사용.

---

## 6. 문의 (contact.tsx)

### 6-1. 폼이 카드 1개에 모두 담겨 SCAN 부담
- "기본 정보 / 사업 정보 / 메시지" 3개 그룹으로 헤더 분리.

### 6-2. 입력 포커스 상태가 약함
- `focus:ring-1 focus:ring-gold` → `focus:ring-2 focus:ring-gold/40 focus:border-gold` (가시성↑).

### 6-3. 제출 후 confirmation
- 단순 메시지만 표시 → "다른 페이지 둘러보기"(서비스/계약 링크) CTA 2개 추가.

---

## 7. 프로세스 (process.tsx)

- 5단계 ol 리스트가 깔끔하나, **각 단계 간 시각적 연결선(타임라인 좌측 세로선)** 부재 → 좌측에 `border-l border-gold/20` + 단계 숫자에 골드 점 마커 추가하면 "프로세스" 인지가 즉각적.

---

## 8. 사례 페이지 (cases.tsx)

- `keyStats` 6개 카드의 정보 밀도 높음 → 데스크톱 `grid-cols-3`, 모바일 `grid-cols-2` 유지하되, source 출처를 `text-[10px] truncate`로 통일.
- 사례 타임라인의 `phase` 라벨(발생/의심 징후/감사·수사/결과)이 텍스트만 → 단계별 작은 골드 dot 아이콘 추가로 흐름 인지 향상.
- "더 보기" 버튼이 단순 텍스트로 끝나는 경우 시인성 약함 → 골드 outline 버튼.

---

## 9. 다크모드 / 접근성

- `.dark` 토큰은 정의되어 있지만 사이트는 항상 라이트. **다크모드 토글은 도입하지 않음**(브랜드 정체성: parchment 기반).
- `text-foreground/70`, `text-muted-foreground`가 곳곳에 사용되는데 `oklch(0.45 ...)`는 라이트 배경에서 WCAG AA 경계선 → 본문은 최소 `text-foreground/85`로 상향.
- 포커스 링이 거의 모든 인터랙티브 요소에서 약함 → 글로벌 `:focus-visible` 스타일을 styles.css에 추가.

---

## 10. 모션·미세 디테일

- 현재 호버 트랜지션이 `transition-all`로 광범위. 가급적 `transition-colors` 또는 `transition-[transform,box-shadow]`로 축소(성능·자연스러움).
- 골드 `hairline` 디바이더를 섹션 헤더 하단에 표준 패턴으로 도입(현재 services 외에는 미사용).
- Hero 이미지에 매우 미세한 grain/noise 오버레이(`opacity-5`)로 인쇄물 느낌 강화 — 브랜드 톤과 어울림.

## 구현 순서 (단계별)

1. **글로벌 토큰/유틸 정비**
   - `src/styles.css`: 본문 대비 상향, `:focus-visible` 글로벌 스타일, `--shadow-gold` 추가, `.btn-gold / .btn-ink / .btn-outline` 유틸 또는 shadcn `Button`에 `gold` variant 추가.

2. **공통 컴포넌트 정리**
   - `SiteHeader`, `SiteFooter`, `PageHero`의 CTA·로고 톤 정리, 관리자 링크 가시성 축소.

3. **페이지별 적용**
   - 홈 → 시뮬레이터 → 계약 → 서비스 → 사례 → 프로세스 → 문의 순으로 위에서 정리한 항목 반영.

4. **반응형 QA**
   - 모바일(360px), 태블릿(768px), 데스크톱(1280px+) 3개 뷰포트에서 시뮬레이터 테이블·계약 카드·문의 폼 중심으로 점검.
