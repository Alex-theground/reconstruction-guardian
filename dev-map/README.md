# 개발예정구역 3D 지도

정비구역 경계와 계획 수치(용적률, 최고층수)로 개발 후 건물 볼륨을 추정해, 실제 서울 지도 위에서 연도별로 보여주는 웹페이지입니다.

```
dev-map/
├─ web/                     # 정적 웹앱 (서버 불필요, 정적 호스팅 가능)
│  ├─ index.html
│  ├─ app.js                # 지도, 타임라인, 패널
│  ├─ massing.js            # 구역 폴리곤 → 계획 건물 볼륨 생성
│  └─ data/zones.geojson    # 표시할 구역 데이터
├─ scripts/
│  ├─ make_sample.py        # 데모용 샘플 구역 생성
│  ├─ build_zones.py        # 공공데이터 → zones.geojson 변환
│  ├─ fetch_seoul.py        # 서울 실제 구역 데이터 받기·변환
│  ├─ ntfc_extract.py       # 결정고시 새 고시 찾기·고시문 수치 추출
│  ├─ plans.csv             # 구역별 계획 수치(고시·보도)
│  ├─ mapping.example.json  # 원본 컬럼명 매핑 예시
│  └─ plans.example.csv     # 고시문 계획 수치 예시
└─ prototype-3d.html        # 1단계 가상 도시 프로토타입
```

## 실행

```bash
cd web && python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 엽니다. 파일을 더블클릭해서 열면 데이터를 불러오지 못합니다.

## 실제 데이터 갱신 (인증키 불필요)

```bash
pip install pyshp pyproj shapely
python3 scripts/fetch_seoul.py --refresh
```

1. **구역 경계**: 서울 열린데이터광장 OA-20957 '의제처리구역 위치정보' SHP의 최신 파일을 내려받습니다. 정비구역, 재정비촉진지구, 시장정비구역만 씁니다.
2. **진행단계**: 서울시 정비사업 정보몽땅 사업장 목록에서 진행 중인 사업장만 가져옵니다. 준공, 이전고시, 해산, 청산 단계는 뺍니다.
3. **연결**: SHP의 조서번호(WTNNC_SN)와 정보몽땅 '지도' 코드가 같으면 바로 연결합니다. 코드가 없으면 구역명으로 연결하되, 구역 번호(③, 1-1, 14단지)와 사업 종류(재건축/주택정비형/도시정비형)가 같아야 하고, 같은 이름 경계가 여럿이면 가장 최근 지정된 경계를 씁니다. 가로주택·소규모 사업은 이름으로 연결하지 않고, 재정비촉진지구 전체 경계와 옛 구역들이 함께 쓰는 자리표시 조서번호(AGZ00000000…)는 쓰지 않습니다. 한 경계에 사업장이 여럿 붙으면 코드 > 이름 일치 > 이름 유사 순으로 고릅니다. 이름은 같지만 다른 사업으로 확인된 옛 경계는 `NAME_LINK_SKIP`에 있습니다.
4. **좌표**: UPIS 좌표계(Bessel, 중부원점 수정)를 데이텀 변환값까지 넣어 WGS84로 바꿉니다. 한남3구역은 OSM 공사현장 폴리곤과 92%, 둔촌주공은 100% 겹치는 것으로 검증했습니다.

2026년 10월 30일 실행 결과: 진행 중인 사업장 923곳 가운데 324곳이 경계와 연결됐고, 313개 구역이 저장됐습니다(준공 4곳 제외). 연결되지 않은 599곳은 대부분 가로주택정비, 지역주택, 리모델링처럼 이 SHP에 경계가 없는 사업입니다.

### 추정값과 실제값

- 계획 용적률과 최고층수는 사업유형별 기본값으로 추정합니다(`fetch_seoul.py`의 `PLAN_GUESS`).
- 착공과 준공 시점은 현재 단계로 추정합니다(`YEARS_TO_START`).
- 결정고시문의 실제 값은 `scripts/plans.csv`에 구역 id(조서번호)별로 넣고 `--plans scripts/plans.csv`로 실행하면 반영됩니다. 형식은 `plans.example.csv`를 참고하세요.

### 결정고시 자동 추출 (`scripts/ntfc_extract.py`)

```bash
python3 scripts/ntfc_extract.py              # 고시 목록 갱신 → 구역별 새 고시 찾기 → 고시문 PDF 수치 추출
python3 scripts/ntfc_extract.py --only-alt   # 변경안(alt)이 있는 구역만 (변경 결정 고시 추적)
python3 scripts/ntfc_extract.py --apply ID1,ID2   # 확인한 구역의 추출 값을 plans.csv에 넣기
```

1. 서울도시계획포털 결정고시 목록(`getNtfcList.json`, 2010년 이후 약 9,200건)을 `scripts/.cache/ntfc/index.json`에 받아 둡니다. 처음에는 약 15분, 다음부터는 마지막 고시일 30일 전부터만 받습니다.
2. 구역명·사업장명·단지명에서 지명+번호(예: `미아3`, `개포주공67단지`, `압구정2`, `신길10`)를 뽑아 고시 제목과 맞춥니다. 번호 사이 말을 지울 때 숫자가 붙지 않게 `|`를 남기고('대선제분 1구역 제5지구' → `대선제분1|5`), 번호 없는 이름 뒤에 번호가 오면(영천↔영천1) 다른 구역으로 봅니다. 두 글자 단지명은 원래 이름에서 '아파트·구역'이 바로 뒤따를 때만 씁니다(은마). 번호 뒤에 숫자가 이어지면(장위1↔장위14), 지명 앞에 다른 글자가 붙으면(가락삼익맨숀↔삼익맨숀) 다른 구역으로 봅니다. 구청 고시는 같은 자치구 구역에만 붙이고, 이름에 '촉진'이 있는 구역은 제목에도 '촉진'이 있어야 합니다.
3. `plans.csv`의 note·source_url에 적힌 고시번호보다 늦은 고시만 '새 고시'로 봅니다(적힌 번호가 없으면 `--since`, 기본 2024-01-01 이후).
4. 새 고시의 첨부 PDF를 `pdftotext -layout`으로 읽어 용적률(가장 큰 값 = 법적상한), 최고층수('최고 N층', 'N층 이하'), 높이(m), 세대수('주택공급계획 : N세대' 우선), 동수를 뽑습니다. 스캔본은 표시만 합니다.
5. 결과는 `scripts/ntfc_report.md`(사람이 읽는 보고서)와 `scripts/ntfc_candidates.csv`(구역별 후보 값, 용적률·층수 후보 전체 포함)입니다. **plans.csv는 자동으로 바꾸지 않습니다.**

정확도(원문 확인된 plans.csv 46행과 비교): 용적률 26행·최고층 29행·세대수 33행이 정확히 일치합니다. 나머지는 반올림(499↔500), 변경 전후 값, 부대시설 표의 세대수가 섞인 경우라 원문 확인이 필요합니다. 'N층 이하'는 높이 상한이라 실제 설계 층수와 다를 수 있습니다.

### 계획 건물의 높이와 모양 (`web/massing.js`)

- **높이**: 1층(필로티) 4.5m + 층고 2.9m × 층수 + 옥탑 6m. 최고층은 구역 중심 동에 두고, 나머지는 중심·북쪽이 높고 남쪽·가장자리가 낮아지도록 최저~최고층 사이에서 배분합니다(일조·경관).
- **동 형태**: 탑상형 십자(4세대 코어), Y자, 경계부 ㄱ자, 판상형(입면을 2m 엇갈린 일자형), 소규모 사업은 2~3세대 판상형, 도시정비형은 저층 포디움 + 업무·주상복합 타워.
- **배치**: 남향(대지 축을 30°까지만 따름), 동 사이 남북 간격은 건물 높이의 0.5배 이상, 탑상형은 줄마다 엇갈리게 놓고 단지 전체에 고르게 퍼뜨립니다. 큰 단지는 가장 긴 경계를 따라 2층 상가동을 둡니다.
- **동 수**: `buildings` 값이 있으면 그대로, 없으면 용적률로 필요한 연면적을 채우는 만큼 계산합니다. 탑상형이 절반도 안 들어가는 좁은 대지는 판상형으로 바꿔 다시 배치합니다.
- **격자 시작점**: 동 수가 정해졌는데 후보지가 모자라면 격자 시작점을 1/3씩 옮겨 9가지 배치 중 가장 많이 들어가는 것을 씁니다(구로우성 2동→5동).
- **동 보충**: 좁거나 모양이 불규칙한 대지라 동이 모자라 연면적이 계획의 75%에 못 미치면, 남은 땅에 소형 판상동을 간격을 최대 30% 좁혀 채웁니다(도곡삼호 0.26→0.79).
- **용적률 맞추기**: 연면적이 계획 용적률의 90%에 못 미치면 최고층 외 동을 최고층수 안에서 올립니다. 용적률 400% 이상(상업지역 주상복합)은 남는 연면적을 2~8층 포디움(상가·업무·오피스텔)으로 채웁니다. 도시정비형은 포디움 층수(3~10층)로 맞추고, 그래도 넘치면 타워 바닥을 최대 60%까지 줄입니다. 화면의 '볼륨 기준 용적률'에는 포디움·상가 연면적도 포함됩니다.
- 구분이 주택정비형이어도 이름에 도시정비형·도시환경이 있으면 주상복합·업무 배치로 그리고, 이런 구역은 세대수로 용적률을 역산하지 않습니다.
- 2026년 10월 보정 결과(계획 용적률 대비 볼륨 용적률): 여의도 한양 44%→99%, 마포로1-10 12%→104%, 영등포1-11 48%→104%, 신길13 37%→100%, 용적률 400% 이상·도시정비형 45곳의 중앙 오차 45%→6%, 전체 중앙 오차 20%→4%(2026.10.30 313곳 기준 4.4%, 0.6 미만 0곳, 1.5 초과 0곳). 은마(91→92%)·한남5(102→103%)는 그대로입니다.
- **변경안**: `alt`가 있으면 변경안 볼륨을 따로 만듭니다. 변경안에 없는 용적률은 고시값을 쓰고, 동 수·최저층은 변경안에 있을 때만 씁니다.
- **실제 수치**: `plans.csv`의 `max_floors`, `min_floors`, `buildings`, `units`, `far`가 있으면 그 값을 씁니다. 용적률이 없고 세대수만 있으면 세대당 연면적 약 115㎡로 용적률을 역산합니다.
- **현재 건물**: OpenStreetMap의 높이(층수) 정보를 그대로 씁니다. 서울은 아파트 층수 입력률이 높은 편이지만 저층 주택은 높이가 없어 기본값으로 보일 수 있습니다. 더 정확한 높이는 국토부 GIS건물통합정보(V-World, 인증키 필요)로 바꿀 수 있습니다.

### 화면 동작

- 구역 안의 현재 OSM 건물은 철거 전까지 주황색(철거 예정)으로 표시됩니다.
